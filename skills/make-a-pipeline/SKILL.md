# make-a-pipeline

One job at a time. A pipeline is worth building only for a job that has come back three or more times and will come back again. For anything else, do the job.

## 1. Pick the job

Name it in the person's words ("the Monday newsletter", "new client onboarding", "the month-end report"). Say back the last three times it was done, from the undo history or the weekly brief, so they can see it really repeats. If they say it will not come back, stop.

## 2. Ask four questions, one at a time

1. "What comes in to start it?" A file, an email forwarded, a date, a message.
2. "What do you do with it, step by step?" Let them talk. Write each step as they say it. A step they do by hand because the answer needs judgment stays a human step.
3. "What comes out, and who gets it?" A file, a draft to send, a folder, a number.
4. "Where do you want to look before it moves on?" This becomes the check. Put it early, where a mistake is cheap, not at the end.

Say the four answers back in four lines. Build only on a yes.

## 3. Build it

In the folder the map names for this kind of work, one subfolder per stage, numbered in order, each holding one `contract.md` under a screen long:

```
Input: what this stage reads
Do: the step, in the person's words
Output: what it writes, and the file name pattern
Check: what the person looks at before the next stage runs, or "none"
```

Add a `README.md` at the top with the trigger line the person will type ("the newsletter draft is in, take it from here") and the stage order. A step that has one right answer every time (rename by date, pull a total, resize an image) gets a small script in the stage folder; check it once against a run the person did by hand.

Then add one row to the router file: the trigger phrase, the pipeline folder, and what to load. The map stays a map; the pipeline folder holds the detail.

## 4. Run it once together

Run the first real job through it with the person watching. Stop at every check. Fix the contract that was wrong, not the output. Save with the `undo` skill after.

## Never

- Build a second pipeline in the same conversation. One, run once, then the next.
- Build for a job that has happened fewer than three times, unless the person insists.
- Turn a judgment step into a script. If the right answer depends on taste or on a fact only the person knows, it stays a human step with a check.
- Write a contract longer than a screen, or a rule the person did not say.
- Send, post, publish or pay from inside a pipeline. Those stay a human step, every time.
